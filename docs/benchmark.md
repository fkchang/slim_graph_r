# Authoring-size benchmark

Source counts measured 2026-09-08; generated SVG refreshed for 0.3.0. Using tiktoken 0.14.0, `o200k_base` encoding. Fixtures are under `examples/benchmark/`.

| Representation | UTF-8 bytes | Tokens |
| --- | ---: | ---: |
| Ruby DSL | 233 | 76 |
| Mermaid | 140 | 42 |
| Manually written SVG | 1,595 | 619 |
| SVG generated by SlimGraphR | 3,632 | 1,273 |

All represent Draft → Ready? → Publish/Revise, with Yes/No branch labels and the title Publishing. The Mermaid fixture does not reproduce the editorial skin; the manual SVG is a compact hand-positioned reference with its own geometry. They are semantic comparisons, not pixel-identical outputs. The generated SVG includes scoped theme styling, accessibility metadata and automated routing.

On this example, the Ruby author writes about 88% fewer tokens than the manual SVG (76 vs 619). Mermaid remains shorter (42). The renderer emits more SVG than the manual reference, which is fine: that text is produced by code rather than authored by an agent. No LLM generation run was performed; this measures tokenizer counts of source, not measured model billing or end-to-end prompt costs. Reference loading, tool overhead, and font assets are excluded.

A 100-render sample on Ruby 3.3.5 took about 0.5 ms per render, including layout and SVG serialization. This is an informational local observation, not a performance guarantee or a dense-graph benchmark.

Reproduce layout timing and generated output:

```sh
ruby examples/benchmark/run.rb
```

Reproduce token counts with Python and tiktoken installed:

```python
from pathlib import Path
import tiktoken
enc = tiktoken.get_encoding('o200k_base')
for name in ['diagram.rb', 'diagram.mmd', 'manual.svg', 'generated.svg']:
    source = Path('examples/benchmark', name).read_text()
    print(name, len(source.encode()), len(enc.encode(source)))
```
